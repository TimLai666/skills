# Ultrathink

## Overview

從任務相關的程式碼、文件、交付物與實際結果取得線索，依疑點查閱外部資料或做驗證，再用思考框架整理證據、推導方案與檢查反例。

理解現況時，分清已確認的需求與限制、既有設計選擇及待驗證假設。保留跳脫現有做法、跨領域借鏡與從基礎事實重新推導的空間。

依問題選擇合適方法。六語分析與完整謬誤檢核依下列條件自動啟用，也可由使用者明確指定。

## Input Contract

從對話取得要解決的問題、目的、已有資料及限制。已知資訊直接沿用，只問會改變結論或授權範圍的缺項。

資料不足時，先查證能查到的部分。缺口不影響建議的，可標明假設繼續。會影響結論的，暫不下該結論，說明缺什麼及如何補足。來源無法存取時，使用可核對的替代來源或標明限制。其他可獨立處理的部分繼續。

## Workflow

1. **界定問題與完成條件**：確認這次要做的決定及判準。複合任務只在需要各自下結論時拆開，已決定的方向不重新開題。
2. **取得線索與證據**：實際閱讀與問題直接相關的內容，沿引用、依賴或資料流追查重要前提。依下節的來源選擇與適用判斷補充資料，優先查會改變決策的缺口。現有脈絡已提供足夠證據時，直接分析。
3. **選擇方法並推導**：用工具索引選能處理當前疑點的方法，查閱所需段落。以已查證事實與明示假設比較方案，提出可檢驗的新解釋或構想。使用者指定方法時，保留該方法必要的步驟與自檢。
4. **查證推論與反例**：檢查最可能推翻建議的證據、失敗情境與連鎖影響。推導期間隨時查閱外部研究與既有做法，核對關鍵前提。需要觀察才能回答時，在授權範圍內做最小實驗，記錄條件與結果。
5. **收斂與完成**：依下節停止條件形成建議，說明成立條件與剩餘不確定。若已授權實作，接續完成約定產出與驗證。只要求討論或審查時，交付相應結果。

## 證據取得與適用判斷

每次查閱先指出要確認的主張或要拓展的選項，再選最可能提供答案的來源。來源種類依問題選擇，不要求每次全部查過。

| 要確認的內容 | 優先查閱與核對 |
| --- | --- |
| 當前實作、流程或成果如何運作 | 相關程式碼、設定、文件、交付物、測試與執行紀錄。核對版本及前後文，區分目前行為與預期結果。 |
| 方法是否成立、在哪些條件有效 | 官方文件、原始研究與學術文獻。核對研究方法、樣本或資料、比較條件、限制與適用範圍。 |
| 別人如何解決類似問題、有無不同做法 | 開源專案的實作、測試、issue、PR 與版本紀錄。確認重現條件、討論結論、實際修改及驗證結果。 |
| 外部現況、經驗或跨領域線索 | 網路資訊、案例與討論。追到可核對的原始來源，確認時間、情境及是否只是轉述同一份資料。 |

線索用來決定查哪裡。支持結論的證據須實際讀過，能指出來源位置及成立條件。搜尋摘要、他人主張或模型記憶先作線索，不能單獨充當查證結果。

論文發表、PR 合併或別人的測試通過，只能支持其實際驗證的主張與條件。比較版本、輸入、環境與目標的差異，再判斷能否套用到目前任務。相互引用或轉載的資料不重複計為獨立佐證。

區分已觀察或查證的事實、由事實推得的結論，以及尚待驗證的假設。證據衝突時查明條件差異，保留無法裁決的部分。新構想沒有現成案例時，可以提出並說明驗證方式，不把缺少先例當成不可行。

### 何時繼續、何時停止

下一輪應能補充關鍵證據、排除假設、發現有實質差異的選項，或完成尚缺的推導與邏輯檢查。若缺的是可查事實，先查資料。若需要觀察，先做實驗。沒有上述用途時，不重跑框架或換語言改寫相同理由。

重要事實主張已有適用證據，推導已檢查前提與邏輯，主要反例已檢查，剩餘不確定不會改變當下行動或已明確限制結論時，就停止蒐集與分析。仍會改變決策但暫時無法驗證的缺口，改成交付具體查證行動，不用更多推演代替答案。

## 選用的深入複核

兩項各依自己的啟用條件判斷。先依證據取得與停止條件確認複核要解決的疑點，缺資料時優先補資料。

- **六語分析**：已有可核對的資料，但對其解釋、推導或重要取捨有實質分歧，且獨立複核可能改變判斷時，自動啟用。使用者明確要求時也啟用，缺資料的主張保留待驗證。依 [multilingual-thinking.md](references/multilingual-thinking.md) 讓六種語言各自分析同一問題，查證所需資料，再核對分歧與證據。不以文化差異為前提，不預先分配角色或觀點。翻譯資料或指定輸出語言本身不是啟用依據。
- **完整謬誤檢核**：結論依賴多層且互相牽動的論證，局部檢查不足以確認是否成立時，自動啟用；使用者明確要求完整清單、七組逐條或地毯式檢核時也啟用。依 [fallacy-checklist.md](references/fallacy-checklist.md) 執行。

## Output Contract

先給結論或建議，再說必要的依據、取捨、成立條件及未解決事項。重要主張附可核對的檔案位置、原始資料連結或實際驗證結果，推論說明依賴的前提。資料不足以裁決時，改給缺口與查證方式。格式與詳略依任務，不固定輸出狀態碼、路由表或完整工作筆記。

使用者要求說明分析過程時，提供可核對的依據、方法摘要與判斷理由。原有 `show_thinking` 請求也依此處理，不輸出內部逐步思考紀錄。

## Quality Rules

- 方法要用在當前問題上，不只複述定義；不以語言數、框架數或勾選數證明品質。
- 本 skill 的模型說明與示例用來選用方法。引用其中的事實、引文或案例支持任務結論時，另行核對原始來源與適用條件。
- 框架的所有分支與 subagent 都沿用上述證據要求。可獨立查閱資料，回傳來源與限制，由主 agent 核對影響決策的主張。
- 不捏造資料、案例、分數或尚未發生的驗證結果。已知、推論、假設與未知要分清。
- 不為支持既定答案挑選工具。出現反例或新證據時，重新評估受影響的判斷。
- 不以多數意見取代查證。額外分析或獨立複核應解決實際疑點。
- PDCA 等跨階段方法尚未完成時，交代已完成部分、待做部分與續行條件；不得聲稱完整循環已完成。
