# 分析鏈完整邏輯

完整報告依下列順序分析。局部研究沿用相關上游依據，不額外生成未要求的整份報告。課堂模式的數量與門檻以 [區段規格](03-section-specs.md) 為準。

## 總覽：分析鏈的流向

```
生態系地圖（了解所有利害關係人）
    ↓
PESTEL（外部環境掃描，各因素評分）
    ↓ [移交包：機會池＋威脅池，依優先分排序]
五力分析（競爭格局，切換成本，替代品）
    ↓
SWOT（S/W 來自公司自身，O/T 承接外部環境與產業證據）
    ↓ [比較 SO/WO/ST/WT 策略]
主要策略選擇（有比較理由）
    ↓
STP（區隔、目標與定位承接環境、競爭、能力及需求證據）
    ↓
商業模式圖（震央從 SWOT+五力推導）
    ↓
顧客 Persona（從 STP 目標客群 + 有來源事實萃取）
    ↓
服務藍圖（以 Persona 為主角，五個內容層與三條分界線）
    ↓
顧客旅程地圖（以 Persona 為主角，真實摩擦，情緒分數）
```

---

## 各分析層的輸入輸出規格

### 生態系地圖

**輸入**：公司名稱、業務描述
**核心問題**：這個服務的生態系裡，誰是供應方、誰是需求方、誰是競爭者、誰是監管者？
**輸出**：Mermaid 圖（分層結構）

**逐項檢視的角色與關係：**
- 核心組織、使用者與其他需求方。
- 資金來源及投資方，相關時附已查證的輪次與金額。
- 技術或知識來源。創辦人曾任職的公司不自動等同技術提供者，須有能力累積、授權或合作依據。
- 上游供應、內容、品牌或其他合作方。
- 交易、導購或服務交付目的地及通路，依服務型態判斷。
- 直接競爭者與替代方案，依需求、市場及服務方式分類。
- 相關監管機構與規則。

每一類都判斷是否相關，未知列出待查內容，不以沒有資料當成不適用。用中心參與者與交換內容決定分組，不固定為投資或電商層。

**統一圖例：**
- 實線箭頭：已確認的合作、資金或服務流，標出交換內容。
- 虛線箭頭：已確認的間接影響或歷史關係，標明內容及時間。
- 無方向線：競爭關係。
- 待確認的關係：在線上文字標「待確認」並交代疑點，不用虛線單獨代表未知。

### PESTEL 分析

**輸入**：公司背景、業務性質
**核心問題**：外部環境中，哪些宏觀因素在推動或阻礙這個業務？
**輸出**：評分表 + 各因素詳細說明 + SWOT 移交包

**評分系統：**
```
優先分 = 重要性(1-5) × 影響程度(1-5) × 時效性(1-3)
最高分：75（5×5×3）
門檻依模式設定：課堂模式見區段規格；一般研究依目的說明篩選依據
```

每一軸須說明評分理由。重要性衡量與研究目標的關聯，影響程度衡量衝擊深度，時效性區分近期、中期與長期。若沿用 1–3 的時效量尺，3 為近期、2 為中期、1 為長期，並明列本案時間視窗。

一般研究可沿用三軸評分，但不把 48 當成通用納入門檻。除分數外須考慮與問題的關聯及重大風險，說明納入與排除理由。課堂模式依其設定執行。

**六個面向的典型因素：**
- Political（政治）：監管政策、平台審查、進出口限制
- Economic（經濟）：市場規模、退貨成本、VC 投資趨勢
- Social（社會）：用戶行為轉變、社群文化、人口結構
- Technological（技術）：核心技術成熟度、大廠技術進場、開源替代
- Environmental（環境）：ESG、碳排、永續壓力
- Legal（法律）：AI 法規、隱私法、智財

**SWOT 移交包格式：**
```
機會池（O候選，依優先分排序）：
  [編號] 因素名稱｜優先分：X｜簡要說明
  ...

威脅池（T候選，依優先分排序）：
  [編號] 因素名稱｜優先分：X｜簡要說明
  ...

觀察項（未達門檻）：
  [編號] 因素｜升級條件：...
```

### 五力分析

**輸入**：PESTEL（競爭環境），生態系地圖（競爭者清單）
**核心問題**：這個產業的競爭結構是什麼？公司的議價空間在哪裡？
**輸出**：五力判斷（含等級）+ 競爭者清單

**五力評估維度：**

1. 現有競爭者的競爭強度
   - 直接競爭者（服務相同需求及市場，有具名案例與來源）
   - 間接競爭者與替代方案（包括其他滿足需求的方式）
   - 競爭強度等級：低/中低/中/中高/高

2. 新進者威脅
   - 技術門檻（是否可用開源替代）
   - 資本門檻
   - 現有玩家的護城河

3. 替代品威脅
   - 替代品的覆蓋範圍
   - 替代品可以取代與無法取代的工作，以及價格、便利性與轉換條件

4. 供應商議價能力
   - 核心技術依賴（是自研還是外採）
   - 內容/品牌合作方的可替代性

5. 買方議價能力
   - B2C 切換成本（低/中/高）
   - B2B 客戶的選擇多寡

**關鍵輸出**：買方切換成本的判斷（影響 BMC 震央選擇和 STP 定位）

---

### SWOT 分析

**輸入**：PESTEL 移交包，五力分析，公司調研
**核心問題**：公司的優劣勢是什麼？外部有什麼機會和威脅？
**輸出**：有編號與依據的 S/W/O/T 清單，課堂模式依規定數量，一般研究按有效差異整理

**配置規則：**
- S（優勢）：公司內部，有事實來源的競爭優勢
- W（劣勢）：公司內部，有事實來源的限制或不足
- O（機會）：承接 PESTEL 機會池及產業分析，標原分析編號與篩選理由
- T（威脅）：承接 PESTEL 威脅池及產業分析，標原分析編號與篩選理由

**策略組合與比較：**

| 類型 | 推導問題 |
| --- | --- |
| SO | 哪項優勢能把握哪個機會？ |
| WO | 哪個機會能協助補足劣勢？ |
| ST | 哪項優勢能降低威脅？ |
| WT | 如何降低劣勢與威脅共同造成的損失？ |

策略標示來源組合，例如 `SO1 [S2×O1]`，說明行動及預期機制。四類都檢視，一般研究不固定每類數量，課堂模式各兩個。沒有足夠證據時記錄缺口，不編造可行策略。

主要策略從目標貢獻、可行性、資源與風險比較後選出。引用相關環境因素、公司能力及需求證據，說明勝過其他策略的原因，不預設從 ST 類挑選。創辦人或媒體引言可作佐證，不能取代比較。

---

### STP 分析

**輸入**：已篩選的 PESTEL、五力、SWOT、主要策略及使用者需求證據
**核心問題**：應該服務誰？如何讓他們選擇我們而非競爭者？
**輸出**：S（區隔維度與客群）、T（三軌篩選矩陣）、P（定位句 + 競爭對照表）

**S（區隔）設計邏輯：**
- 每個區隔維度須說明需求、行為或市場證據，並交代相關 PESTEL 因素與競爭條件。課堂模式另依門檻規則
- 維度切割要能清楚分出不同的用戶群
- 二維交叉可產生 4 個區隔，三維交叉可產生 8 個

**T（目標）三軌篩選矩陣格式：**
| 區隔 | PESTEL（標因素編號與優先分） | 五力結構 | SWOT 能力 | 結論 |
|------|--------------------------|----------|-----------|------|
| AX | ... | ... | ... | [判斷及理由] |
| BX | ... | ... | ... | [判斷及理由] |
| AY | ... | ... | ... | [判斷及理由] |
| BY | ... | ... | ... | [判斷及理由] |

選擇或排除區隔時，說明需求、競爭與能力的綜合判斷。矩陣中的代號只用來辨識客群，不能預先指定主要目標。

**P（定位）推導邏輯：**
1. 說明選定主要策略要解決的機會、威脅或能力問題。
2. 結合目標客群的需求與選擇條件。
3. 提出價值主張、差異及支持差異的能力或證據。
4. 與目標客群實際會考慮的替代方案比較，確認定位與主要策略一致。

若主要策略是 ST，可從優勢如何應對威脅推導；SO、WO、WT 則按各自的機制推導，不套固定的 S×T 句型。

### 商業模式圖（BMC）

**輸入**：SWOT、五力、STP
**核心問題**：公司靠什麼創造、傳遞和捕獲價值？
**輸出**：震央選擇依據表 + 九格商業模式圖

**震央是創新設計的起點，依本案可改變的要素比較：**

| 起點 | 檢視問題 |
| --- | --- |
| 資源導向 | 是否有可轉用或稀缺的資源、能力與合作關係？ |
| 顧客導向 | 哪些未滿足需求、關係或服務情境能驅動改變？ |
| 財務導向 | 收益、定價或成本結構是否是本次改變的核心？ |
| 產品導向 | 產品或價值主張的改變會如何帶動其他要素？ |

列出選擇依據與比較理由，不因切換成本低就排除顧客導向。研究現況時先描述有依據的九格，設計建議另標示。

**九格與設計順序：**

九格均需檢視：關鍵資源、價值主張、目標客群、通路、顧客關係、關鍵活動、關鍵合作夥伴、收益流、成本結構。由選定起點向相關要素展開。

資源導向的順序示例：關鍵資源 → 價值主張 → 目標客群 → 通路 → 顧客關係 → 關鍵活動 → 關鍵合作夥伴 → 收益流 → 成本結構。

核心要素深入分析。資料未知標示待查，尚未決定的方案要素標示待驗證，不因財務數字未公開就略過收益與成本的運作機制。

完整報告保留以下分析：
- 差異化策略地圖：假說、機制、防禦性、主要風險。
- 驗證實驗：目標要素、方法、成功指標、決策規則。課堂模式使用 30 天規劃，一般研究依實際時程。
- 從降低劣勢與威脅到發揮優勢、把握機會的路徑，說明成立條件；無法形成時交代原因。

### 顧客 Persona

**輸入**：STP 目標客群、有來源的 beta 用戶/實際用戶資料
**核心問題**：目標客群的行為、需求與限制如何具體呈現？
**輸出**：Persona 屬性表格（每列有依據與推論標示）+ 核心痛點 + 核心動力

**屬性來源查詢順序：**
1. 實際使用者的訪談、研究或具名報導（檢查情境與代表性）
2. App Store / 評論平台的具體描述（有代表性的評論）
3. 創辦人對目標用戶的自述（二手，需標注）
4. 公司策展/合作內容暗示的客群（推論，需說明推論邏輯）

Persona 是複合人物，不冒充受訪者。角色代稱可自訂並標明用途，職業、年齡、地點與偏好則需來源支持，否則保留未知或不填。公司合作品牌僅能提供可能客群的線索，不能直接證明使用者的偏好。推論列出資料、推導理由及不確定性。

### 服務藍圖

**輸入**：Persona、BMC 的服務傳遞分析
**核心問題**：服務在前台和後台是如何被傳遞的？哪裡有缺口？
**輸出**：五個內容層（前台可分子層）× N 個階段的表格 + 缺口診斷表

**五個內容層與三條分界線（縱軸）：**
1. 服務實證（Physical Evidence，含實體與數位物件）
2. 用戶行動（Customer Actions）
3. ── 互動線（Line of Interaction）──
4. 前台（Frontstage）：按需要區分科技與真人互動，實際存在的接觸點均須納入
5. ── 可視線（Line of Visibility）──
6. 後台（Backstage）
7. ── 內部互動線（Line of Internal Interaction）──
8. 支援流程（Support Processes，含內部支援與外部系統）

互動線區分使用者與服務方，可視線區分可見前台與不可見後台，內部互動線區分直接交付服務的活動與其他支援流程。

**流程階段（橫軸）**：根據服務特性與分析範圍設計，不用固定階段數
- 建議命名格式：「動詞 + 核心動作」（如：發現、試用、使用、購買、分享）

**缺口診斷表格格式：**
| 缺口位置 | 問題描述 | 嚴重程度及理由 | 來源依據 | 相關 SWOT | 建議方向 |
|---------|---------|---------|---------|---------|---------|

新發現的缺口先保留證據，若影響 SWOT 判斷再回頭更新，不為了對應編號硬套劣勢。

### 顧客旅程地圖（CJM）

**輸入**：Persona、服務藍圖的流程階段、真實用戶反饋
**核心問題**：Persona 從認知到使用的完整情緒旅程是什麼？
**輸出**：多欄位旅程表格 + 情緒分數明細表

**必要欄位（縱軸）：**
- 動機
- 行動
- 情緒曲線（含數字分數）
- 接觸點
- 感受 / 關鍵時刻
- 科技服務
- 行銷方法
- 目標

**情緒分數規則：**
- 每個分數須有真實使用者回饋或測試紀錄支持。將文字轉為分數時，標明這是研究者依量尺判斷，不是使用者原始評分
- 列出支持正面及負面感受的證據，各自標來源。沒有某一面的資料時說明缺口，不編造平衡
- Aha Moment 若有前提條件，要明確標注

**關鍵時刻（⚡）標記**：
- ⚡ = 中等摩擦點（有影響但可接受）
- ⚡⚡ = 嚴重摩擦點（可能導致用戶流失或核心需求無法被滿足）

**情緒分數明細表格式：**
| 階段 | 情緒分數 | 正面證據與來源 | 負面證據與來源 |
|------|---------|-----------------|-----------------|


情緒量尺：1 為極度負面或放棄，2 為負面，3 為中性，4 為正面，5 為強烈正面。依整體證據判斷，沒有明確計算規則時不任意加減分。缺少某階段的回饋時標「未知」，不能以中性 3 分補位。示意性的情境推演須另標為假設，不能稱為真實 CJM。

不同人、版本與使用情境的評論不能無條件串成同一條旅程。說明 Persona 的綜合依據、共同情境及差異，保留會影響體驗的條件。
