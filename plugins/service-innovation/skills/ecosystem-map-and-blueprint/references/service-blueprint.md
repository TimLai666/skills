# 服務藍圖 Service Blueprint

### 定義
從**服務提供者視角**，展示前台（使用者可見）與後台（幕後）元素如何串聯的完整流程圖。

### 適用時機
1. **改善服務效率**：找出服務傳遞中的延遲、斷點、低效節點
2. **提升員工體驗**：當前端體驗已完善，轉而優化後台人員操作流程
3. **服務成形後**：確立與使用者的互動模式及各部門職責分野
4. **既有服務改良**：釐清服務結構，找出可供改善的點

### 五個內容層與三條分界線

| 層次 | 名稱 | 說明 |
|------|------|------|
| 頂部 | **服務證據 (Physical Evidence)** | 使用者接觸到的實體或數位證據（App 介面、包裝、收據等） |
| 第二層 | **顧客旅程 / 使用者行為** | 使用者在整個消費行為中的各項步驟 |
| — | **互動線 (Line of Interaction)** | 使用者與服務方的接觸邊界 |
| 第三層 | **前台 (Frontstage)** | 服務方中使用者**可見**的行為（含科技層面） |
| — | **可視線 (Line of Visibility)** | 區分可見前台與不可見後台 |
| 第四層 | **後台 (Backstage)** | 使用者不可見、支撐前台工作的幕後行為 |
| — | **內部互動線 (Line of Internal Interaction)** | 區分直接支撐顧客互動的前後台活動與其他支援流程 |
| 底部 | **支援流程 (Support Processes)** | 支援服務交付的內部團隊、第三方平台、外部機構與基礎設施 |

### 三條基準線詳解

#### 互動線 (Line of Interaction)
- **線之上**：使用者活動（註冊、付款、簽收）
- **線之下**：前台工作，可按需要分兩子類：
  - **科技互動（Tech Layer）**：APP介面、Email折扣碼自動折抵、訂餐表單
  - **真人互動**：宅配員送餐簽收、發送實體傳單

數位接觸點必須完整標示。真人與科技互動需要分開追蹤時，再拆出 Tech Layer，不要求每張圖都有獨立科技子層。

#### 可視線 (Line of Visibility)
- **線之上**：使用者看得見的前台服務
- **線之下（後台）**：使用者看不見但必須存在的流程
  - 例：後台更新菜單、接收訂單後採購食材、倉儲人員裝箱

#### 內部互動線 (Line of Internal Interaction)
- **線之上**：直接交付服務的前台及其後台活動。
- **線之下**：支援前後台工作的其他流程，可以由內部團隊或外部供應商負責。
- 例如內部系統維護、第三方金流串接、電子報系統維護都可能是支援流程。依具體活動與交接關係分類，不按公司內外直接決定位置。菜品研發、供應商審核、剩餘食材交接也須依本次服務範圍判斷。


### 互動符號系統

| 符號 | 意義 | 使用時機 |
|------|------|----------|
| → 單向箭頭 | 資訊推送（單向傳遞） | 發送傳單、系統通知 |
| ⇄ 雙向箭頭 | 雙向交換或對話 | 使用者詢問過敏源↔客服回覆 |
| ⚡ 閃電符號 | 流程缺口 / 痛點 | 標示低效、斷點及待改善的節點 |

圖例須說明箭頭與缺口符號的意義。雙向箭頭不保證互動即時。缺口須描述發生條件與影響，再評估刪除步驟、調整分工、改善交接或引進科技，不能由符號直接推導解法。


## 繪製流程

1. 選定使用者類型、服務起訖及現況或未來方案。
2. 匯入既有顧客旅程（CJM）的步驟與接觸點，先核對是否符合本次範圍。沒有 CJM 時，依現有材料整理使用者行為，標示待確認處。
3. 沿時間順序填入使用者行為、前台、後台、支援流程與服務證據，用三條線區分各層。
4. 補上負責角色、跨層交接與方向。系統名稱要搭配實際動作，不能用名稱代替流程。
5. 標示延遲、斷點、錯誤與改善機會。例外可用分支或註記，若影響閱讀則另繪藍圖並標明分歧及返回位置。
6. 依主檔的完整清單檢查，將未確認的責任與交接交由相關人員驗證。

## YouBike 服務藍圖教學示例

原稿註記「工具表單 #10」，未附可追溯來源。以下保留其教學情境，不作為 YouBike 現行服務或內部流程的事實描述。

- **顧客旅程**：獲得資訊 → 前往出租站 → 註冊 → 租車 → 騎車 → 還車。
- **前台**：廣告宣傳、提供站點資訊、機器註冊介面、刷卡租車介面、地板白線提示。
- **後台**：查詢站點地圖與自行車數量資料、處理會員及卡片資料。
- **支援流程**：行銷團隊支援宣傳、各站點車輛調度、系統維護團隊維護服務。
- **服務證據**：DM 文宣、App／網站、註冊機器、租車刷卡機、自行車、車架。

這份分層清單是繪圖材料。實際交付時，須把每項活動對齊旅程步驟，補上負責者與跨層連結。角色可能同時負責不同層的活動，例如調度人員搬運車輛是否屬於前台，取決於該情境下使用者是否看得到。
