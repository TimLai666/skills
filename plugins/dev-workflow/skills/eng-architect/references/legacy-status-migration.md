# Legacy status migration

Earlier versions used `delivery-plan.md` for status. It must not be mistaken for a feature plan by a `*-plan.md` search.

Read the existing file and project instructions before changing it. If it is the legacy status record and the project has no different established arrangement, explain the rename to `delivery-status.md` and preserve the content with `git mv` when authorized. If both names exist, compare them and resolve their roles before writing; do not overwrite or leave competing status sources. Update affected references in the authorized scope. A project intentionally using its own status filename keeps that arrangement.
