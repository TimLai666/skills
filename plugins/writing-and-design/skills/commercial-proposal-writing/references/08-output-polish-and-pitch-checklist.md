# Output Polish And Pitch Checklist

依任務範圍檢查，無關項目不適用。純審查交付發現，局部改稿只驗證修改內容與相關上下文。

## 1. 最終健檢

- [ ] 本次資料缺口已查找、核對並補齊；受阻部分有查找結果與具體取得方式，沒有因缺資料而省略必要內容
- [ ] 使用假設草案時已獲使用者接受，並明示尚缺的決策證據
- [ ] `Why -> What -> How -> Proof -> Ask` 完整
- [ ] 決策所需內容與使用者指定結構完整
- [ ] Ask 具體且可執行
- [ ] 財務、KPI、時程前後一致
- [ ] 假設、驗證方式與失效影響已說明

## 2. 常見錯誤 checklist

- [ ] 沒有空洞開場
- [ ] 沒有只貼產業報告
- [ ] 沒有把問題寫成「大家都有」
- [ ] 沒有 KPI 無推導
- [ ] 沒有競品名單式分析
- [ ] 沒有功能導向而缺結果
- [ ] 沒有只列通路不證明有效
- [ ] 沒有只放甘特圖不建立信任
- [ ] 沒有財務數字無推導
- [ ] 沒有隱藏風險
- [ ] 沒有缺 Ask
- [ ] 沒有翻譯腔與空話

## 3. 簡報前檢查（有簡報需求時）

- [ ] 開場 30 秒內就知道問題與代價
- [ ] 2 分鐘內講清楚方案與差異化
- [ ] 5 分鐘內講清楚數字邏輯
- [ ] 結尾有清楚 Ask 與下一步

## 4. 10 分鐘提案結構範例

- 開場鉤子：2 分鐘
- 問題與方案：3 分鐘
- 數字與證據：2 分鐘
- Ask 與下一步：3 分鐘

## 5. 何時不能交付

完整提案若存在下列問題，不得宣稱已可送審。仍可交付明示缺口的草案或審查意見：

- Ask 還是模糊的
- 數字無法被追問
- 風險完全沒寫
- 決策者看不出為什麼現在要做
