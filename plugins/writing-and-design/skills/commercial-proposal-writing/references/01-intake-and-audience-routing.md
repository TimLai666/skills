# Intake and Audience Routing

## 1. 明確界定這份企劃要誰說 Yes

完整提案依決策需要釐清以下資訊。局部改稿與審查只補問會影響本次結果的資料：

- `proposal_type`: `internal|fundraising|partnership`
- `audience`: 決策者、影響者、使用者
- `decision_goal`: 要推動什麼決策
- `ask`: 要批准的資源、金額、合作承諾或下一步
- `problem_statement`
- `target_customer`
- `available_evidence`
- `goal_kpi`
- `budget`
- `timeline`

## 2. 模式判定

- 有題目、想法、草綱，沒有完整正文 -> `generate`
- 已有稿件、要求改寫 -> `rewrite`
- 只要求審查 -> `review`，不自動改寫

若是 `review`，但沒原稿或沒關鍵段落，先查找已提供的附件與指定文件；仍找不到才要求補件。

## 3. 受眾路由

### `internal`

重點看：

- 為什麼現在要做
- 要投多少資源
- ROI 與回收期
- 執行風險與 Go/No-Go

### `fundraising`

重點看：

- 市場機會
- 為什麼是現在
- 為什麼是這個團隊
- 成長敘事與資金用途

### `partnership`

重點看：

- 雙方價值交換
- 角色分工
- 合作機制
- 成功後的下一步

## 4. `tone_profile=auto`

- `internal -> executive_formal`
- `fundraising -> investor_formal`
- `partnership -> consulting_formal`

若受眾明確提到政府、標案、法遵、審議，再覆寫為 `gov_formal`。

## 5. 資料不足時先補齊

1. 列出影響本次成果的缺口，先查對話、原稿、附件及已授權存取的專案資料。
2. 可由外部查證的資料，主動搜尋原始或官方來源，核對日期、適用對象與統計口徑，保留出處。不得把產業平均直接當成公司的實績，也不得用機密資料作公開搜尋。
3. 已有原始數據但缺指標時，依可驗證的公式計算，交代輸入與推導。需要額外調查或訪談時，提出具體蒐集方式；對外聯絡前取得授權。
4. 經查找仍無法取得，或屬於使用者才能決定的預算、目標與承諾時，說明查過哪些來源、還缺什麼、影響哪個判斷，再提出精準問題。可獨立完成的部分繼續處理。
5. 必要資料尚未補齊時，保留該缺口及取得方式，不以刪除章節、標示限制或套入假設取代補資料。只有確認不適用於任務的內容才能省略。

## 6. 補齊受阻後的選擇

若確實無法取得資料，依缺口與時程提出下一步：請使用者提供內部資料、安排調查，或在使用者接受假設草案時產出情境試算。不得預設選擇假設版。

假設草案須明示假設、驗證方式及失效影響，不能宣稱已具備正式決策所需證據。純審查則回報實際查證結果與尚未解決的缺口。
