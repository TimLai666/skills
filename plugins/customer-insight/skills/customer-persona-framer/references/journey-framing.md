# 選用旅程前置

使用者明確要求顧客旅程前置分析或指定 journey-framing 時閱讀。本模式沿用主檔的人物誌，不重建已足夠的客群資料。

## 必要資料

旅程前置需要顧客輪廓、產品或服務及相關使用情境。缺少會改變階段與接觸點的資訊時，先詢問或標明受影響部分，人物誌可先交付。依主檔草稿規則作出的假設須一併標示，不把缺少必要資料的區塊當成可完成旅程地圖的交接。

## 前置分析

在人物誌後整理：

1. **5W1H 摘要**：誰（Who）、做什麼（What）、何時（When）、在哪裡（Where）、為何（Why）、如何（How）。已在人物誌說明的內容引用該欄，其餘補足旅程情境。
2. **旅程五元素摘要**：人物誌、階段、接觸點、情緒及指標。人物誌引用 persona_block，階段沿用下項定義。接觸點使用搜尋、LINE、門市、客服等具體對象，情緒描述顧客感受與變化，指標須可觀察。
3. **階段定義**：沿用使用者指定名稱及順序，否則預設認知、考慮/研究、決策/購買、使用、關係建立。說明各階段所涵蓋的活動。
4. **交接區塊**：按下列欄位整理供 customer-journey-mapper 使用的必要內容。

前置分析保留各方法的檢查範圍，重複資訊用引用串接。指標留在前置摘要，不追加到旅程地圖交接區塊。

## 交接區塊

使用 `handoff_to_customer_journey_mapper` 作為區塊名稱，保留原有欄位並帶入階段：

| 欄位 | 交接內容 |
| --- | --- |
| 顧客輪廓 | 包含核心需求、相關限制與使用情境的精簡描述 |
| 產品或服務 | 本次分析對象 |
| 品牌/產業背景 | 已知且相關的背景 |
| 目標市場 | 本案市場範圍 |
| 目前接觸點 | 已知接觸點及重要條件 |
| 輸出用途 | 旅程分析的使用目的 |
| 自訂階段 | 已採用的階段名稱與順序 |

交接區塊可能單獨傳遞，必要背景與影響判斷的假設須隨內容交付，不只寫「同上」。未知的選用欄位省略或標待確認。使用者明確修正優先於交接內容。

本模式交付至前置分析與交接資料。使用者也要求完成旅程地圖時，再接續 customer-journey-mapper。
